# tests

## Host unit tests

```sh
make -C ../native test      # or ./run-host-tests.sh
```

These check the SIP builder and the RFC 3310 digest against vectors
generated by the postmarketOS implementation that actually achieved
REGISTER 200 on this handset, so they encode a known-good oracle rather
than the C code's own opinion of itself.

## tools/

Two probes kept from bring-up. Neither is part of the build or the zip;
both earned their place by finding real defects.

### `tools/sip-probe.c` (host)

Drives the real `parse_response()` and `build_register()` with a synthetic
401 and prints the exact `Authorization` header that would go on the wire,
including the raw bytes of the `algorithm=` region.

```sh
cc -I../../native/src -o sip-probe \
   ../../native/src/util.c ../../native/src/md5.c \
   ../../native/src/secagree.c ../../native/src/sip.c \
   ../../native/src/config.c sip-probe.c
./sip-probe
```

It found the AKAv2 defect: an AKAv1 challenge and an AKAv2 challenge
produce an *identical* response hash while the header dutifully advertises
whichever was challenged, because `build_register()` discards CK/IK and
only ever computes AKAv1. Still open — see the README's defect list.

### `tools/ctlprobe.c` (device, aarch64)

Minimal ctl client over the abstract unix socket, so it exercises the
authenticated transport rather than the bring-up TCP listener.

```sh
aarch64-linux-gnu-gcc -static -O1 -o ctlprobe ctlprobe.c
adb push ctlprobe /data/local/tmp/ && adb shell chmod 755 /data/local/tmp/ctlprobe
adb shell /data/local/tmp/ctlprobe STATUS
adb shell /data/local/tmp/ctlprobe "CALL sip:+15551234567@ims.example.net"
adb shell /data/local/tmp/ctlprobe HANGUP
```

It is what proved the unix socket plus `SO_PEERCRED` path works end to end
while the IMS app was still failing on it, which separated "our socket is
broken" from "SELinux will not let the app reach it".

## No real identifiers, ever

Everything in this directory uses invented values: the reserved test PLMN
(MCC 001 / MNC 01), `ims.example.net`, and `+15551234567`.

Do not paste a real IMPI, IMSI, MSISDN, P-CSCF address, nonce, RES, CK or
IK into these files or their output. The probes are built so they never
need one — `sip-probe` invents its own challenge, and `ctlprobe` takes the
destination on the command line. Device logs are held to the same standard:
the daemon logs realm, SPIs and ports, never identity or key material.

## Useful counters when the network goes quiet

On-device, these answered more questions than any amount of reading did:

| Where | Tells you |
|---|---|
| `/proc/net/xfrm_stat` | `XfrmOutStateExpired` (SA lifetime left at zero), `XfrmInTmplMismatch` (a decrypted packet dropped by an inbound policy) |
| `ip -s xfrm state` | per-SA byte/packet counters — whether a reply arrived at all, and on which SA |
| `/proc/net/snmp6` | `Ip6FragOKs` (is the packet being fragmented), `Ip6OutNoRoutes`/`Ip6OutDiscards` (is it leaving the handset) |

An inbound SA counting bytes while userspace sees nothing means the packet
arrived and something after decryption dropped it. That distinction is what
turned "the network is silent" into a fixable bug.
