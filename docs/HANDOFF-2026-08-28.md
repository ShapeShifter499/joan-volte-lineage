# Handoff — 2026-08-28

State at end of session: **registration works, outbound calling works,
inbound calling does not. There is no audio on any call.**

Read this before touching anything. Everything below was measured on
device unless it says otherwise.

## What works

- **REGISTER 200 OK**, stable, re-registration scheduled, reproducible
  across daemon restarts.
- **MO (outbound) call**: `INVITE → 100 → 180 → 200 → ACK → BYE 200`,
  verified on a live call to an authorized test number.
- `HANGUP` sends a BYE; an unanswered INVITE is CANCELled at the setup
  timer.

## What does not work

- **MT (inbound) calls.** Implemented, never observed. See below.
- **Audio.** There is no RTP sender or receiver at all. Signalling only.
  Every "working" call above is silent. The pmOS run fed TTS through a
  userspace PCMU sender; earpiece/mic on the IMS session is the separate
  q6voice lane and was never proven even there.
- **Codec.** SDP offers AMR-WB first, but what the network actually
  negotiated has not been checked. Read the 200 OK's SDP to find out.

## MT: what is actually known

An inbound call was placed to the handset. The daemon logged **nothing** —
no INVITE reached it. Two facts frame the next step:

1. The inbound SA counted **1586 bytes / 10 packets**, so the network does
   send us traffic on the protected server port. Until this session
   `ua_handle_inbound()` returned silently on anything that was not a
   request, so those packets left no trace. It now logs every datagram
   with its first line — **check that log first**, it will say whether an
   INVITE is arriving and being mishandled, or not arriving at all.
2. `dumpsys telephony.registry` shows the CS domain registered with
   `availableServices=[VOICE,SMS,VIDEO]` on LTE. That strongly suggests
   terminating calls are being delivered over **CS fallback**, not to our
   IMS registration — i.e. the network does not consider our registration
   authoritative for terminating voice. If so, no amount of fixing the
   inbound socket will help; the question becomes what the registration
   must contain for the core to route terminating calls to it.

Already fixed this session, so do not re-chase: REGISTER advertised port-c
in `Contact` when RFC 3329 puts inbound requests on the protected **server**
port, and nothing read the inbound socket while idle.

## Landmines

These each cost hours. All are fixed; the notes are so they are not
reintroduced.

- **A zeroed `xfrm_lifetime_cfg` is a hard limit of ZERO**, not unlimited.
  SAs expire on first use, `sendto` returns EINVAL, `XfrmOutStateExpired`
  climbs. `ip xfrm state add` fills `XFRM_INF`; raw netlink does not.
- **Policy selectors default to prefixlen 0**, so the addresses are carried
  but ignored for matching.
- **Four SAs share one address pair** with a wildcard SA selector. Without
  `reqid` the kernel cannot tell them apart and may encrypt under the wrong
  SPI. Pin `reqid` on **outbound policies only** — pinning it inbound
  causes `XfrmInTmplMismatch` and the decrypted reply is dropped.
- **Inbound policies are deliberately not installed.** Linux accepts a
  decrypted packet when no inbound policy demands otherwise; requiring one
  cost us the P-CSCF's reply.
- **The P-CSCF answers on the UE's protected server port**, not the client
  port the request went out from. Wait on both.
- **Never put the IMPI in `From`, `Contact` or `P-Preferred-Identity`.** It
  is `IMSI@ims.mnc<MNC>.mcc<MCC>.3gppnetwork.org`; a fallback to it put a
  subscriber's permanent IMSI on screen as the caller ID of a real call.
  The public identity comes from `P-Associated-URI` in the REGISTER 200.
  `build_invite()` now refuses to build without an IMPU.
- **In-dialog requests** (ACK, BYE) go to the remote target from the 2xx
  `Contact`, while `To` keeps the dialled URI plus the To-tag. Conflating
  them returns `481 Call/Transaction Does Not Exist`.
- **Verify on device, never trust the edit.** A pre-existing
  `su->reqid = 0;` later in the same function silently clobbered a fix; the
  only reason it was caught is that `ip xfrm state` still reported
  `reqid 0`.

## Debugging that actually worked

The daemon logs to `/data/vendor/netmgr/joan-ims-ua.log`. If the
`log sink open` banner is missing, the channel is dead and nothing in the
file is evidence. `STATUS` reports the sink state.

| Where | Tells you |
|---|---|
| `ip -s xfrm state` | per-SA byte/packet counters — whether a reply arrived, and on which SA |
| `/proc/net/xfrm_stat` | `XfrmOutStateExpired`, `XfrmInTmplMismatch` |
| `/proc/net/snmp6` | `Ip6FragOKs`, `Ip6OutNoRoutes`, `Ip6OutDiscards` |

An inbound SA counting bytes while userspace sees nothing means the packet
arrived and something after decryption dropped it. That single distinction
turned "the network is silent" into a fixable bug.

## Device workflow

```sh
adb root && adb remount      # /system goes read-only and adbd drops root every reboot
adb push joan-ims-aarch64 /system/bin/joan-ims-ua
adb shell chcon u:object_r:netmgrd_exec:s0 /system/bin/joan-ims-ua
adb shell setprop ctl.restart joan-ims
adb shell /data/local/tmp/ctlprobe STATUS
```

APK changes need a **reboot** — the app is `android:persistent`, so
`pm install -r` refuses it and priv-app is only rescanned at boot. Binary
changes only need the `ctl.restart`.

`tests/tools/ctlprobe.c` drives the ctl channel (`STATUS`, `CALL <uri>`,
`HANGUP`). Build it with `aarch64-linux-gnu-gcc -static`.

## Next steps, in order

1. **Read the new inbound datagram log during an incoming call.** It
   settles whether an INVITE arrives at all. Everything about MT is
   guesswork until that line exists.
2. If nothing arrives, investigate CS fallback: why the core routes
   terminating voice to the CS domain rather than our IMS registration.
3. RTP. Nothing exists. This is what "no audio" means.
4. Dialer wiring, so calls go through the framework rather than a ctl verb
   and inbound calls ring instead of being auto-answered.
5. Open defects listed in the README: hardcoded `cnonce`/`nc`; AKAv2-MD5
   advertised but never computed and quoted `algorithm="..."` silently
   discarded (both block carriers that challenge AKAv2); `hex_decode()`
   partial count.
6. The loopback ctl listener is unauthenticated and is still the only route
   the app has. `upstream/sepolicy/joan_ims.te` is the fix, and is
   **untested** — it cannot be verified from a sideloaded zip.
